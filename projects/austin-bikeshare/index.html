Auditing destination station IDs in Austin bikeshare

I checked which trips would drop out of a station report if I joined the trip records using a numeric destination ID.

Business question

Before reporting arrivals by station, I wanted to know whether every recorded destination could be matched using a numeric station ID. A failed match could quietly reduce the number of trips in the report.

Data and method

I audited the destination station ID in the public Austin bikeshare trips table in BigQuery. I filtered for IDs with a recorded value, then used SQL’s SAFE_CAST to check which values failed conversion to a whole number. I counted the trips that met both conditions.

Results

I found 119 trips with a recorded destination ID that could not be converted to an integer. A report using an inner join on that numeric ID would leave those trips out.

Reporting decision

I would keep those trips in systemwide ride totals and flag them as unresolved in station-level reporting. That keeps the overall trip count intact and makes the station attribution issue visible to the reader.
